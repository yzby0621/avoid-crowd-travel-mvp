## 2. 设计目标

推荐引擎 v1 不是追求“最智能”，而是追求：

1. 结果稳定
2. 逻辑可解释
3. 便于快速调参
4. 支持“换一批”
5. 与“端午避挤”定位一致

核心策略：

> 先过滤，再打分，再排序，再去重，最后输出可解释结果。

## 5. 预处理步骤

推荐前先做统一预处理：

1. 读取目的地 JSON 配置
2. 将用户输入英文枚举映射成配置表中的中文值
3. 初始化每个候选项的中间得分结构
4. 对每个候选生成可解释的“命中原因”与“降权原因”列表，方便 debug

建议内部数据结构：

```ts
interface CandidateDebugInfo {
  matched: string[];
  penalized: string[];
  filteredReason?: string;
}
```

## 6. 过滤规则

推荐引擎先做“硬过滤 + 软过滤”。

## 6.1 硬过滤

满足以下任一条件，可直接剔除：

### 规则 1：出发城市适配度过低
- 条件：`departure_fit[departureCity] < 2`
- 作用：过滤掉明显不适合当前出发城市的目的地

### 规则 2：交通要求强约束不满足
当用户选择 `train_3h` 时：
- 若目的地 `transport_fit` 不包含 `尽量高铁 3 小时内`
- 则直接过滤

### 规则 3：同行人完全不匹配
- 若用户同行人标签不在 `companions_fit` 中
- 则过滤

### 规则 4：旅行偏好完全不匹配
- 若用户偏好标签不在 `preferences_fit` 中
- 则不过滤也可以，但建议先进入软惩罚
- MVP 推荐做“软处理”，避免候选过少

---

## 6.2 软过滤 / 降权

### 规则 5：预算不完全匹配
- 若 `budget_fit` 不包含当前预算档位
- 不过滤，打分时降权

### 规则 6：交通偏好不完全匹配
- 若用户为 `train_or_flight` / `worth_longer`
- 且目的地不完全匹配，也只做轻微降权

### 规则 7：人流敏感度匹配不足
- 若用户是 `very_sensitive`
- 但候选 `holiday_risk_level = high`
- 不直接过滤，但大幅降权

## 7. 打分模型

## 7.1 总分公式

建议基础公式：

```text
totalScore =
  baseScore
  + tierBonus
  + cityPriorityBonus
  + preferenceBonus
  + companionBonus
  + budgetBonus
  + transportBonus
  + crowdFitBonus
  - fatiguePenalty
  - holidayRiskPenalty
```

---

## 7.2 具体项定义

### A. baseScore
来源于配置表已有基础字段：

```text
baseScore =
  duanwu_fit_score * 0.30 +
  avoid_crowd_score * 0.25 +
  departure_fit_score * 0.20 +
  accessibility_score * 0.10 +
  people_fit_score * 0.10 +
  budget_score * 0.05
```

其中：
- `departure_fit_score = departure_fit[departureCity]`

---

### B. tierBonus
```text
A = +0.6
B = +0.2
C = -0.5
```

---

### C. cityPriorityBonus
```text
cityPriorityBonus = city_group_priority[departureCity] * 0.1
```

---

### D. preferenceBonus
```text
匹配 = +0.5
不匹配 = -0.3
```

若用户偏好命中 `preferences_fit`，加分。

---

### E. companionBonus
```text
匹配 = +0.3
不匹配 = -1.0
```

由于同行人很关键，不匹配时应重罚。

---

### F. budgetBonus
```text
匹配 = +0.2
不匹配 = -0.2
```

---

### G. transportBonus
```text
完全匹配 = +0.2
部分匹配 = 0
不匹配 = -0.6
```

---

### H. crowdFitBonus
根据用户人流敏感度和候选风险等级联合计算：

#### 用户 = `very_sensitive`
- `low` = +0.4
- `medium` = -0.3
- `high` = -0.8

#### 用户 = `avoid_if_possible`
- `low` = +0.2
- `medium` = 0
- `high` = -0.4

#### 用户 = `not_sensitive`
- `low` = 0
- `medium` = 0
- `high` = 0

---

### I. fatiguePenalty
```text
fatiguePenalty = fatigue_score * 0.15
```

说明：
- 折腾程度越高，越不适合端午短假

---

### J. holidayRiskPenalty
对 `holiday_risk_level` 再补一层统一风险处理：

```text
low = 0
medium = 0.1
high = 0.4
```

该项用于保证高风险目的地不会轻易进入前排。

## 8. 推荐结果去重逻辑

排序之后，不能直接取前 3 个，需要做去重和风格拉开。

## 8.1 去重目标
避免出现：
- 3 个都属于“美食小城”
- 3 个都来自同一个区域
- 3 个都偏同一种调性

## 8.2 去重规则

### 规则 1：控制 category 重复
如果连续候选的 `categories[0]` 相同，则对后者做轻微降权，或跳过一次。

### 规则 2：控制 region 重复
如果前两个结果已经来自同一省份/区域，则第三个优先选不同区域。

### 规则 3：优先保留高分差异项
如果第 4 名和前 3 名分数接近（差距小于 0.3），但风格明显不同，则可替换第 3 名。

## 9. 换一批逻辑

“换一批”不能完全随机，也不能完全一样。

## 9.1 实现建议

### 方法 A：滑动窗口
- 第一次输出排序后的 `1,2,3`
- 第二次输出 `2,3,4`
- 第三次输出 `3,4,5`

问题：变化可能不够自然。

### 方法 B：可控扰动（推荐）
基于 `refreshSeed` 给每个候选增加一个微小扰动值：

```text
finalDisplayScore = totalScore + noise(refreshSeed, destinationId)
```

要求：
- 扰动值范围小，例如 `[-0.15, +0.15]`
- 不要改变整体质量排序太多
- 只影响边缘名次顺序

推荐做法：
- 先按 `totalScore` 取前 8 个候选
- 对这 8 个加扰动
- 再跑一次去重和选 Top3

## 10. 结果文案组装规则

推荐结果页建议直接复用配置表中的文案字段，避免前端做复杂拼接。

### 10.1 结果卡字段
- `name`
- `tags`
- `reason_short`
- `reason_duanwu`
- `reason_avoid_crowd`
- `risk_tip`
- `alternatives`

### 10.2 tags 生成建议
根据字段自动生成 3~4 个标签：

规则示例：
- `trip_length_fit` 包含 3 -> `适合 3 天`
- `recommendation_tier = A` -> `相对避挤`
- 偏好命中 -> `美食文化` / `自然放空` / `海边度假` / `城市漫游`
- 同行人命中 `情侣` -> `适合情侣`
- 同行人命中 `朋友` -> `适合朋友`

## 11. 推荐引擎伪代码

```ts
function recommend(request: RecommendationRequest, destinations: Destination[]): RecommendationResult {
  const refreshSeed = request.refreshSeed ?? 0;

  const mappedCompanion = companionMap[request.companion];
  const mappedBudget = budgetMap[request.budgetLevel];
  const mappedPreference = preferenceMap[request.travelPreference];
  const mappedTransport = transportMap[request.transportTolerance];
  const mappedCrowd = crowdMap[request.crowdSensitivity];

  const candidates = [];

  for (const d of destinations) {
    if (d.departure_fit[request.departureCity] < 2) continue;
    if (request.transportTolerance === 'train_3h' && !d.transport_fit.includes('尽量高铁 3 小时内')) continue;
    if (!d.companions_fit.includes(mappedCompanion)) continue;

    let score = 0;

    score += d.duanwu_fit_score * 0.30;
    score += d.avoid_crowd_score * 0.25;
    score += d.departure_fit[request.departureCity] * 0.20;
    score += d.accessibility_score * 0.10;
    score += d.people_fit_score * 0.10;
    score += d.budget_score * 0.05;

    score += tierBonus(d.recommendation_tier);
    score += (d.city_group_priority?.[request.departureCity] ?? 0) * 0.1;

    score += d.preferences_fit.includes(mappedPreference) ? 0.5 : -0.3;
    score += d.companions_fit.includes(mappedCompanion) ? 0.3 : -1.0;
    score += d.budget_fit.includes(mappedBudget) ? 0.2 : -0.2;
    score += transportBonus(mappedTransport, d.transport_fit);
    score += crowdBonus(request.crowdSensitivity, d.holiday_risk_level);

    score -= d.fatigue_score * 0.15;
    score -= holidayRiskPenalty(d.holiday_risk_level);

    candidates.push({ destination: d, score });
  }

  const sorted = candidates.sort((a, b) => b.score - a.score).slice(0, 8);

  const perturbed = sorted.map(item => ({
    ...item,
    displayScore: item.score + stableNoise(refreshSeed, item.destination.id)
  }));

  perturbed.sort((a, b) => b.displayScore - a.displayScore);

  const finalThree = pickDiverseTop3(perturbed);

  return buildResponse(finalThree, refreshSeed, candidates.length);
}
```
