# PRD：端午避挤旅行推荐助手（MVP）

## 1. 文档信息

- 产品名称：端午避挤旅行推荐助手
- 版本：MVP v0.1
- 目标上线时间：1.5 周内
- 文档目的：明确 MVP 的产品目标、范围、功能、推荐逻辑、页面结构、数据结构和验收标准，供产品、设计、开发快速对齐并启动实现。

## 2. 项目背景

节假日出行中，用户并不缺少信息，而是缺少适合当前假期条件的决策答案。
尤其对于北上广深年轻人，端午属于典型的短假场景，决策特点为：

- 假期短，容错率低
- 不想路上花太多时间
- 不想去“人从众”的热门目的地
- 不想花很多时间刷攻略做筛选

现有旅游平台大多擅长：
- 热门内容推荐
- 攻略展示
- 交易承接

但对“端午 3 天、我不想人挤人，到底去哪更合适”这一决策问题，缺少足够锋利、轻量、直接的产品体验。

本项目希望做一个超聚焦 MVP，验证以下价值：

> 用户是否愿意使用一个专门解决“端午避开人挤人目的地选择”的工具，并认为其推荐有帮助。

## 3. 产品目标

### 3.1 核心目标
帮助北上广深年轻人在端午节前，快速找到相对不那么拥挤、更适合 3 天短假的旅行地。

### 3.2 MVP 验证目标
验证以下假设是否成立：

1. 用户会因为“端午不想人挤人”这个痛点而点击进入产品
2. 用户愿意输入少量条件获得推荐
3. 用户会认为推荐结果“有帮助”
4. 用户会对特定推荐结果产生兴趣，甚至愿意分享、收藏或再次尝试

### 3.3 非目标
MVP 阶段不解决以下问题：

- 不做完整旅游平台
- 不做机酒预订
- 不做实时价格比价
- 不做复杂 AI 对话规划
- 不做详细行程攻略
- 不覆盖全国所有出发城市
- 不承诺“绝对不挤”，只做“相对更轻松、更稳妥”的推荐

## 4. 目标用户

### 4.1 核心用户
北上广深年轻人，尤其是：

- 年龄：22–35 岁
- 城市：北京 / 上海 / 广州 / 深圳
- 状态：白领、年轻上班族、情侣或朋友结伴出游
- 场景：端午有 3 天假，想出行但没决定去哪
- 核心诉求：
  - 不想人挤人
  - 不想太折腾
  - 想快速做出旅行决策
  - 希望选择“更稳”的地方而不是最热门的地方

### 4.2 用户特征
- 并非没有旅游信息，而是信息太多难以决策
- 更容易被“帮我快速筛选”而非“给我更多内容”打动
- 更关注：
  - 交通成本
  - 节假日拥挤风险
  - 3 天是否值得去
  - 是否适合情侣/朋友短途出游
  - 性价比和体验感

## 5. 核心问题定义

本产品不只是解决“去哪玩”，而是解决：

> 端午这种短假期，去哪更不容易踩坑、不容易人挤人、整体体验更稳。

用户真实问题可拆分为：

1. 不知道去哪
2. 怕选到节假日体验崩盘的地方
3. 不想去最热门的目的地
4. 不想花太多时间自己筛攻略
5. 希望系统直接给少而准的建议

## 6. 产品定位

### 6.1 定位一句话
面向北上广深年轻人的端午“避挤”旅行地推荐工具。

### 6.2 对外价值表达
端午不想人挤人？
帮你根据出发城市、预算和偏好，快速找到更适合 3 天短假的旅行地。

### 6.3 差异化
相较传统旅游平台，本产品的差异化在于：

- 只做端午场景
- 只服务北上广深年轻人
- 不推“最热门”，而是推“更稳、更轻松”的目的地
- 不是内容聚合，而是决策推荐
- 输出少量高质量结果，并解释原因与风险

## 7. MVP 范围

### 7.1 本期必须支持
- 首页承接与价值表达
- 结构化需求输入
- 推荐 3 个目的地结果
- 每个结果展示推荐理由、避挤理由、风险提醒、替代地
- 支持“换一批”
- 支持轻量反馈采集
- 支持北上广深 4 个出发城市
- 支持首批 16–20 个候选目的地

### 7.2 本期可选支持
- “如果你非常怕人多，这次不建议优先考虑”的反向建议模块
- 轻量推荐评分展示
- 分享/复制结果

### 7.3 本期明确不做
- 登录体系
- 个人中心
- 收藏夹
- 实时价格抓取
- 行程规划
- 攻略详情页
- 交易闭环
- 聊天式 AI 交互

## 8. 功能设计

## 8.1 功能 1：首页 / Landing Page

### 目标
- 让用户快速理解产品价值
- 激发点击进入表单

### 页面核心内容
1. 标题：

   - 帮你找到更适合 3 天短假的旅行地

2. 副标题：
   - 面向北上广深年轻人，根据你的出发城市、预算和偏好，推荐相对更轻松的端午目的地

3. CTA：
   - 立即开始推荐
   - 测测我端午适合去哪

4. 补充说明：
   - 我们不是推荐最火的地方，而是推荐更适合端午短假的地方

5. 示例卡片预览（可选）
   - 展示 2–3 个示例目的地卡片，增强信任感

### 交互
- 点击 CTA 进入需求填写页

### 目标
让用户用最少成本输入关键信息，获得推荐。

### 输入字段

#### 必填字段 1：出发城市
- 北京
- 上海
- 广州
- 深圳

#### 必填字段 2：同行人
- 一个人
- 情侣
- 朋友
- 亲子
- 带父母

#### 必填字段 3：预算档位
- 省钱型
- 适中
- 可以稍微住好一点

#### 必填字段 4：旅行偏好
- 轻松逛吃
- 自然放空
- 海边度假
- 城市漫游
- 小众体验

#### 必填字段 5：交通接受度
- 尽量高铁 3 小时内
- 高铁 / 飞机都可以
- 只要值得，远一点也行

#### 可选字段 6：人流敏感度
- 非常怕人多
- 尽量别太挤
- 只要好玩，人多也能接受

### CTA
- 查看我的端午推荐

- 单屏或单页完成，不做复杂分步流程
- 默认值可适当设置，减少填写成本
- 输入校验仅需保证必填项非空

## 8.3 功能 3：推荐结果页

### 目标
输出少而准的推荐结果，帮助用户快速做决定。

### 结果结构
- 输出 3 个目的地
- 按推荐优先级排序
- 结果风格尽量不完全重复

### 页面模块

#### 模块 1：推荐结论
示例：
- 基于你的情况，这个端午更推荐你去这些相对更轻松的地方：

#### 模块 2：推荐卡片列表
每张卡片包含：

1. 目的地名称
2. 标签
   - 适合 3 天
   - 相对避挤
   - 高铁友好 / 飞机友好
   - 适合情侣 / 适合朋友等

3. 一句话推荐结论
4. 为什么适合端午
5. 为什么相对不那么挤
6. 风险提醒
7. 替代目的地
8. 操作按钮
   - 我想看这个
   - 换一个类似的（可选）

#### 模块 3：谨慎选择提示（建议支持）
示例：
- 如果你这次非常怕人多，可谨慎优先考虑以下类型目的地：
  - 超级热门景区型目的地
  - 路程过长的特种兵型选择
  - 节假日价格和人流双高的顶流城市

#### 模块 4：换一批 / 改条件
- 再给我换一批
- 修改条件重新推荐

#### 模块 5：用户反馈
- 这次推荐对你有帮助吗？
- 你最想去哪一个？

### 交互要求
- 结果页首屏必须出现至少 1 个清晰推荐结果
- 点击“换一批”应返回不同结果组合或次优备选
- 修改条件应回到表单页，保留原值可编辑

## 9. 推荐逻辑

MVP 推荐逻辑采用：

> 结构化规则 + 人工 curated 目的地池 + 标签打分

不采用复杂 AI 决策。

## 9.1 推荐流程

### 第一步：过滤
过滤掉明显不适合当前条件的目的地。

过滤条件包括但不限于：
- 与出发城市的可达性不匹配
- 不适合 3 天短假
- 明显超出预算档位
- 与旅行偏好不匹配
- 拥挤风险过高且不符合“避挤”目标

### 第二步：打分
对剩余目的地进行综合评分。

### 第三步：排序
按总分排序，选出 Top 3。

### 第四步：结果去重
避免 3 个结果过度相似，尽量拉开风格差异。

## 9.2 推荐评分维度

每个目的地可从以下维度打分：

### 1. 端午适配度
衡量该目的地是否适合 3 天短假。
考虑因素：
- 行程节奏是否适中
- 到达后是否容易展开体验
- 不需要过多长途转移

### 2. 避挤友好度
衡量该目的地相较头部热门目的地，拥挤风险是否更低。
注意：仅表达“相对更轻松”，不表达“绝对不挤”。

### 3. 可达性
衡量从北上广深对应出发城市过去是否方便。
例如：
- 高铁是否友好
- 飞行时长是否合理
- 总路程是否适合短假

### 4. 人群适配度
衡量目的地是否适合该同行人组合。
例如：
- 情侣适合浪漫、松弛、好逛
- 朋友适合拍照、社交、体验密度高
- 带父母更看重舒适和节奏

### 5. 偏好匹配度
衡量该目的地是否匹配用户的旅行偏好：
- 轻松逛吃
- 自然放空
- 海边度假
- 城市漫游
- 小众体验

### 6. 预算匹配度
衡量该目的地的大致消费水平是否符合用户预算档位。

### 7. 折腾程度（负向指标）
衡量该目的地是否容易出现：
- 路上时间过长
- 中转复杂
- 短假不划算
- 高峰返程压力大

## 9.3 推荐原则

1. 先排除明显不适合的，再推荐
2. 优先推荐“更稳”的地方，而不是“最火”的地方
3. 结果需要可解释
4. 结果不要全是一个类型
5. 推荐文案避免绝对化承诺
   - 用“相对更轻松”“拥挤风险相对更低”“更适合端午短假”
   - 避免“绝对不挤”“冷门无人”

## 12. 页面文案原则

### 12.1 推荐文案要点
每条推荐至少回答 4 个问题：
1. 为什么推荐它
2. 为什么适合端午
3. 为什么相对不那么挤
4. 风险是什么

### 12.2 表达原则
- 避免夸张
- 避免绝对承诺
- 优先用“相对、整体、通常、如果你更在意…”等表达
- 强化“帮你节省决策时间”的价值感

## 13. 用户流程

### 主路径
1. 用户进入首页
2. 理解产品价值并点击开始
3. 填写条件
4. 查看推荐结果
5. 换一批 / 修改条件 / 提交反馈

### 备选路径
- 用户在首页停留但不开始
- 用户填写中退出
- 用户看结果后无感直接离开
- 用户多次尝试不同条件查看结果

## 14. 埋点与验证指标

MVP 重点关注验证指标，而不是复杂业务指标。

### 14.1 转化漏斗指标
1. 首页访问数
2. CTA 点击率
3. 表单完成率
4. 结果页到达率
5. 换一批点击率
6. 反馈提交率

### 14.2 质量验证指标
1. 结果页停留时长
2. 用户是否愿意再次修改条件重试
3. 用户最常点击的目的地类型
4. “有帮助”反馈占比
5. 分享/复制行为（如支持）

### 14.3 最低成功标准
- 用户愿意点击进入
- 大部分用户能完成表单
- 有一定比例用户认为结果“有帮助”

## 15. 非功能要求

### 15.1 性能
- 表单提交后推荐结果应在 1–2 秒内返回
- 首屏加载尽量轻量

### 15.2 设备
- MVP 优先支持移动端 H5
- 桌面端可自适应但不是重点

### 15.3 内容维护
- 候选目的地与文案应可配置，避免写死在前端
- 推荐规则尽量参数化，便于后续快速调整

## 16. 风险与注意事项

### 16.1 主要风险
1. 推荐结果过于泛，用户觉得“别的平台也有”
2. “避挤”承诺过强，引发信任问题
3. 候选池太小导致推荐重复感强
4. 推荐逻辑不透明，用户不信服
5. 页面信息过多，影响转化

### 16.2 应对建议
1. 强化“为什么适合端午”和“为什么相对更轻松”的解释
2. 避免绝对化表述
3. 加“换一批”
4. 增加“谨慎考虑目的地类型”模块，提升专业感
5. 保持页面结构简单直接

## 18. 验收标准

### 功能验收
1. 用户可完成表单输入并成功获得结果
2. 结果页可返回 3 个推荐目的地
3. 每个结果含推荐理由、端午适配说明、避挤说明、风险提醒、替代地
4. 用户可点击“换一批”
5. 用户可修改条件重新推荐
6. 用户可提交轻量反馈

### 内容验收
1. 所有候选目的地均有完整结构化数据
2. 推荐文案无明显夸张或失实表达
3. 首页价值表达清晰
4. 结果解释具备一致性与可读性

### 体验验收
1. 页面流程简洁顺畅
2. 移动端展示正常
3. 推荐返回速度可接受
4. 无明显阻塞型 bug

## 19. 后续迭代方向

如果 MVP 验证有效，可考虑后续迭代：

1. 扩展节日场景：
   - 暑期
   - 国庆
   - 周末短途

2. 扩展人群：
   - 亲子
   - 银发
   - 单人短逃离

3. 扩展结果能力：
   - 推荐后的简版 itinerary
   - 目的地对比
   - 不建议去某地的解释
   - 轻度交易承接
