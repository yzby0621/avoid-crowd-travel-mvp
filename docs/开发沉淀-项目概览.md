# 项目概览：端午避挤旅行推荐助手

## 1. 项目定位

这是一个面向 **北上广深年轻人** 的端午节旅行推荐 MVP，核心目标不是做泛旅游攻略，而是解决一个更具体的决策问题：

> 端午 3 天假，不想人挤人，到底去哪更合适。

产品价值不是提供更多旅游内容，而是帮助用户在节前快速缩小选择范围，找到 **相对不那么拥挤、整体体验更稳、更适合短假** 的旅行地。

---

## 2. 当前明确的业务结论

### 2.1 核心用户
- 城市：北京 / 上海 / 广州 / 深圳
- 年龄：22–35 岁
- 人群：年轻白领、情侣、朋友结伴出游用户为主
- 特征：
  - 有出游意愿
  - 不缺信息，但难做决策
  - 对节假日体验质量敏感
  - 不想去“人从众”的热门目的地
  - 不想把短假花在赶路和排队上

### 2.2 核心场景
- 第一阶段只做 **端午节**
- 场景本质：3 天短假下的目的地决策
- 核心矛盾：
  - 想出行
  - 但不想人挤人
  - 又担心路上太折腾、去错地方不值

### 2.3 核心卖点
- **不想人挤人**
- 更准确表达为：
  - 推荐 **相对更轻松** 的目的地
  - 避开节假日体验容易崩盘的高风险选择
  - 帮用户优先排除不适合端午短假的地方

### 2.4 差异化定位
与传统旅游平台相比，本项目的差异化在于：
- 只服务端午决策场景
- 只服务北上广深年轻人
- 不推最热门，而推更稳、更轻松的目的地
- 不是攻略聚合，而是决策推荐
- 输出少而准的推荐结果，并说明原因与风险

---

## 3. MVP 目标

### 3.1 产品目标
帮助北上广深年轻人在端午节前，快速找到 **相对不那么拥挤、更适合 3 天短假的旅行地**。

### 3.2 验证目标
验证以下假设：
1. 用户会因为“端午不想人挤人”这个痛点而进入产品
2. 用户愿意输入少量条件获得推荐
3. 用户会认为推荐结果“有帮助”
4. 用户愿意继续尝试、换一批、或修改条件重试

### 3.3 本期不做
- 不做旅游交易闭环
- 不做实时价格比价
- 不做复杂 AI 对话
- 不做详细行程攻略
- 不覆盖全国所有城市
- 不承诺“绝对不挤”

---

## 4. MVP 范围

### 4.1 必做能力
- 首页价值承接
- 表单式需求输入
- 输出 3 个推荐目的地
- 每个结果包含：
  - 推荐理由
  - 为什么适合端午
  - 为什么相对不那么挤
  - 风险提醒
  - 替代目的地
- 支持“换一批”
- 支持轻量反馈采集
- 支持北上广深 4 个出发城市
- 支持首批 16–20 个候选目的地

### 4.2 可选能力
- 反向提示模块（这次可谨慎优先考虑的类型）
- 轻量评分展示
- 分享/复制结果

---

## 5. 产品形态

### 5.1 页面结构
MVP 采用三页结构：

1. **首页 / Landing Page**
   - 说明价值
   - 引导开始推荐

2. **需求填写页**
   - 用户输入条件

3. **推荐结果页**
   - 展示 3 个推荐目的地
   - 可换一批
   - 可改条件
   - 可提交反馈

### 5.2 表单字段
#### 必填
- 出发城市：北京 / 上海 / 广州 / 深圳
- 同行人：一个人 / 情侣 / 朋友 / 亲子 / 带父母
- 预算档位：省钱型 / 适中 / 可以稍微住好一点
- 旅行偏好：轻松逛吃 / 自然放空 / 海边度假 / 城市漫游 / 小众体验
- 交通接受度：尽量高铁 3 小时内 / 高铁或飞机都可以 / 只要值得远一点也行

#### 可选
- 人流敏感度：非常怕人多 / 尽量别太挤 / 只要好玩人多也能接受

## 6. 推荐策略

MVP 使用：

> **结构化规则 + 人工 curated 候选池 + 标签打分**

不做复杂 AI 推荐。

### 6.1 推荐流程
1. 过滤不适合当前条件的目的地
2. 对候选目的地打分
3. 选出 Top 3
4. 做结果去重，避免 3 个结果过于相似

### 6.2 核心打分维度
- 端午适配度
- 避挤友好度
- 可达性
- 人群适配度
- 偏好匹配度
- 预算匹配度
- 折腾程度（负向）

### 6.3 推荐原则
- 先排除不适合的，再推荐
- 优先推荐更稳的地方，而不是最火的地方
- 推荐结果必须可解释
- 结果不要全是同一类
- 文案避免绝对化承诺，使用“相对更轻松”“更适合端午短假”等表达
