# Railway 部署说明 - MVP

## 1. 为什么优先推荐 Railway

对于当前这个项目，Railway 很适合做第一版线上部署，因为：

- 项目本身是一个简单 Node 服务
- 已经有 GitHub 仓库
- 已经有 `npm start`
- 部署流程很短
- 很适合 MVP 尝试和外部测试

## 2. 当前项目的部署准备情况

当前项目已经具备：

- `package.json`
- `npm start`
- Node HTTP 服务入口：`src/server.js`
- GitHub 仓库已公开
- `.env.example` 已存在

并且已经将默认监听地址改为：

- `HOST=0.0.0.0`

这更适合 Railway / Render 等平台部署。

## 3. Railway 最短部署步骤

### 第一步：登录 Railway

打开 Railway 官网并登录。

### 第二步：创建新项目

选择：

- **Deploy from GitHub repo**

然后选择仓库：

- `avoid-crowd-travel-mvp`

### 第三步：等待自动构建

Railway 会自动识别 Node 项目并执行：

- install：`npm install`
- start：`npm start`

### 第四步：配置环境变量（如需要）

如果平台没有自动注入，可手动加：

- `HOST=0.0.0.0`

通常 `PORT` 由平台自动注入，不需要手动写死。

### 第五步：拿到公开访问链接

部署成功后，Railway 会提供一个可公开访问的网址。

这个网址就可以：

- 自己在手机上测试
- 发给朋友试用
- 后续作为小红书的承接页

## 4. 部署成功后建议立即检查的事项

### 页面层
- 首页是否正常打开
- 表单是否可操作
- 点击推荐是否返回结果
- 换一批是否正常

### 内容层
- 页面标题是否够清楚
- 是否一眼看懂是“节假日旅行地推荐”
- 是否能体现“不想人挤人”这个卖点

### 手机端层
- 手机打开是否错位
- 首屏是否能快速理解
- 结果卡片是否容易阅读

## 5. 上线后适合做什么

第一阶段上线目标不是正式运营，而是：

- 给熟人试用
- 给小红书评论区用户试用
- 自己在不同设备上体验
- 验证用户是否真的愿意用“输入条件 → 获得推荐”的方式决策

## 6. 上线后的下一步建议

1. 跑一轮真实外部测试
2. 收集用户最常留言的出发地和偏好
3. 看哪些推荐结果最容易被认可
4. 再回头优化候选地配置表和推荐解释文案
